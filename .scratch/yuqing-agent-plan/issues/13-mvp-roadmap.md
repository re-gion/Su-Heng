# 13 MVP范围与分期路线图

Type: grilling
Status: resolved
Blocked by: 07, 08, 11, 12

## Question

综合已定决策，划定MVP边界：v1包含哪些agent、哪些数据源、专报哪些板块；v2及远期（如扩展为监测预警全平台）放什么；每期的验收标准（什么叫"可用"）；开发顺序与里程碑。

## Answer

用户决策（2026-08-12）：**三步走**，原则=每个阶段都有可演示交付物。

**M0 骨架竖切（先跑通端到端）**
范围：单agent（事实调查）+ 证据库（SQLite，快照存证）+ LLM交叉核验（四级徽章）+ 速览版HTML报告 + SSE流式 + 每轮state落盘。
验收：零配置（免费搜索链+单一低成本LLM）输入事件名→产出带可点击引用的速览报告；进程中断后可从最近状态续跑；重要claim 100%绑定evidence_id。

**V1（MVP，可参赛演示）**
范围：三分析agent并行（事实调查/媒体传播/历史洞察-按需回溯模式）+ 论坛黑板 + 主持人评审（增益评估+硬上限双Loop）+ 综合报告agent；完整版专报（十板块、四级核验、速览/完整双版、传播图表用证据库真实口径）；SSE论坛过程前端可视化；配置页（多LLM角色三元组+搜索API多家兜底）；搜索API用户文档。
验收：引用覆盖率100%（重要claim）、核验通过率按信源加权口径展示、局限性声明必出、断点续跑可演示、单次完整分析在可配token预算内完成、非技术用户按README能在10分钟内跑出第一份专报。

**V1.5（数据纵深+交付完善）**
范围：历史数据层完整（公开数据集一键导入 + 热榜快照定时积累入SQLite）→历史对照板块升级为真实数据驱动；PDF导出（图表转静态）；报告IR稳定化；演示站部署。
验收：新事件专报可叠加热榜真实热度数据；历史对照卡片来自本地库检索；PDF与HTML内容一致且引用保留。

**V2（远期增强）**
范围：用户自带Cookie的深度评论可选插件（默认关闭、风险声明）；本地NLI核验增强；多语言/境外信源扩展。
（舆情监测与预警平台化仍在本地图Out of scope，属另起effort的愿景。）

开发顺序：M0→V1→V1.5 串行推进，每阶段结束做一次真实事件全流程演示验证。
