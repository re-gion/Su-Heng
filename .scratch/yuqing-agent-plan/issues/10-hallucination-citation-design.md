# 10 幻觉控制与引用可核验机制

Type: grilling
Status: resolved
Blocked by: 09

## Question

设计端到端的数据真实性机制：引用溯源的数据结构与展示格式（每个重要数据/事实附来源、可点击回溯）；多agent/多源互证的实现方式；置信度分级（如：多源证实/单源/存疑）；"不知道不说、不编造"在提示词与流程上的落实；搜索结果原文的存证方式（便于事后核验）。这是本产品的可信度生命线，机制要嵌进架构而不是靠提示词祈祷。

## Answer

用户决策（2026-08-12）：**自动核验=LLM交叉核验**（低成本异构模型逐claim比对引用原文；本地NLI模型留作V2可选增强）。端到端机制设计如下（细节在SPEC票落实）：

1. **证据先行的数据流**：所有搜索/抓取结果先入证据库（SQLite）：evidence_id、URL、标题、发布时间、来源域名、正文抽取、原文快照存档、抓取时间。agent产出的每个重要claim必须引用已存在的evidence_id——从机制上杜绝"编造来源"（引用的东西必然真实存在、可回看）。
2. **claim结构化**：{claim文本, evidence_ids[], agent, 轮次}，JSON schema约束产出。
3. **LLM交叉核验**：核验器（与生成agent异构的低成本模型，如deepseek）逐claim比对引用原文片段→支持/部分支持/不支持+理由。映射三级标记：**已证实**（≥2独立信源支持）/**待核验**（单源或部分支持）/**争议**（信源矛盾或核验不支持但claim保留展示）。多源互证=同claim被多个独立域名证据支持时升级。
4. **信源分级**：内置可配置的域名可信度分层（官方通报>主流媒体>门户/聚合>自媒体>未知），随引用展示，不同层级在核验权重中区分。
5. **"不知道不说"三层落实**：提示词层（明确指令）+ 机制层（无evidence_id的重要claim渲染层拒绝进入专报正文）+ 呈现层（未解决项进"局限性声明"板块，承接09大Loop强制放行的未解决清单）。
6. **展示与回溯**：专报中claim点击/悬浮显示引用卡片（来源、发布时间、原文片段、快照链接）；证据快照本地留存可离线核查；专报附证据清单附录；HTML与PDF均保留引用。
7. **可量化验收指标**（进入13验收标准）：重要claim引用覆盖率、核验通过率、争议项显性率——这是08"可量化差异化"的落地。

## Amendment (2026-08-12, 由11号票样张评审修订)

1. 三级标记升级为**四级**：已证实 / 待核验 / 争议 / **已证伪**（证据充分否定流传说法时使用，深红徽章）。
2. 核验规则补充：**官方/标准文本级单源可直接判"已证实"**（展示时注明单源官方）；核验通过率指标按信源等级加权口径注明。
