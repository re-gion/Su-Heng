# 07 历史洞察Agent的取舍与替代路径

Type: grilling
Status: resolved
Blocked by: 04

## Question

历史洞察Agent依赖"提前用爬虫积累历史舆情数据库"，是全项目最重、风险最高的一块（数周积累周期、风控、合规）。基于社媒数据获取调研结果，决定它的路径：自建爬虫持续积累 vs 用公开数据集/热榜存档 vs 按需回溯搜索（用搜索API查历史报道替代自建库）vs 砍掉该agent、把历史视角并入其他agent。产出明确决策与理由。

## Answer

用户决策（2026-08-12）：**保留历史洞察Agent，数据层重构为"三层合规轻数据"**，放弃原PRD的"提前爬虫囤历史库"计划。

三层结构：
1. **冷启动**：公开数据集（微博热搜历史小时级数据、话题舆情数据集等）一键下载入库，解决"装好就有历史可查"；
2. **运行时积累**：用户部署后自动定时抓取热榜快照（DailyHotApi模式，MIT合规）存本地SQLite，越用越厚；
3. **深度回溯**：搜索API时间过滤（如智谱oneDay~oneYear）按需查询历史报道，覆盖连续数据之外的深度需求。

社媒深度评论采集降级为"用户自带Cookie、默认关闭、风险自担"的可选插件，不作为核心依赖（对比BettaFish：其InsightEngine无库即报废，本设计三层各自独立降级）。

依据：[04 国内社媒数据获取现实调研](04-social-data-access.md)——自建爬虫囤库有判例级法律风险（微博诉蚁坊案）、无法随开源产品分发；合规替代可覆盖约60-70%需求；"历史相似事件对照"是BettaFish与Deep Research都没有的差异化空档（见06调研）。

后续影响：历史数据层细节（数据集选定与打包、快照调度、表结构、插件边界）进入雾区，等架构与技术栈票（09/12）定型后在SPEC中落实。
