## 2. 两套推荐组合

### 2.1 零付费链（默认，适合先试试看）

```
中文搜索：LangSearch（零费用优先） → Exa（记录费用估算，无本地月限额） → 百度千帆 → 博查
境外搜索：Exa → Tavily → Serper
正文取得：搜索 Provider 返回的全文 → 内置 httpx+trafilatura 直抓 → Firecrawl Cloud 兜底
```

- LangSearch 当前 $0，千帆/博查有试用或体验资源；Exa、Tavily、Serper 和 Firecrawl 的免费额度、是否需要支付方式及消耗规则各不相同，不能把整条链写成“全部免费、无需绑卡”。
- 限制：LangSearch 不再按固定“每天 1000 次”计量，而按输入/输出 token、RPS、TPM、TPD 管理；具体 TPD 在账户 Dashboard 查看。千帆未确认控制台权益前按 50 次/日、1500 次/月保守保护。触顶、429 或结果不足时逐级降级。

### 2.2 质量优先链（推荐，花费很低）

```
中文搜索：LangSearch → Exa → 百度千帆 → 博查
境外搜索：Exa → Tavily → Serper
原文抓取：Provider 全文 → 内置直抓 → Firecrawl Cloud
```

- 本次只对一个具体中文事件和一组历史案例检索做了受控在线对照；这不能推出 Exa 在所有中文事件上都优于其他服务。
- 博查可用试用/体验资源包做固定查询集验证；不能把服务商宣传或低价体验包写成稳定生产质量、长期单价或“与 LangSearch 索引独立”的证明。

### 2.3 我该选哪个？

| 你的情况 | 建议 |
|---|---|
| 只想先跑起来看看效果 | 零付费链 |
| 在意报告质量、愿意花几块钱 | 先用默认国内顺序做固定查询集，再按增量覆盖决定是否购买博查；智谱仍可手工加入，但不是本轮默认链 |
| 需要分析境外/英文相关事件 | 按 Exa → Tavily → Serper 配置境外链；需要时再做真实网络和中文覆盖探针 |
| 部署在境外服务器 | 仍先复用搜索 Provider 返回的全文，再用内置直抓；关键失败页可配置 Firecrawl Cloud |
| 部署在国内服务器 | 默认使用内置直抓；Firecrawl Cloud 只作为关键页面的受控回退，不把外部抓取服务作为默认前置 |
| 有海外 VPS 且想零边际成本 | 自建 SearXNG（进阶配置，见 §5） |

## 5. 原文抓取服务

搜索 API 返回的全文也不等于本系统从目标 URL 保存的直接快照。Provider 文本可以用于筛选、阅读和要点转述，但必须标为 Provider 全文；需要逐字引用、哈希和日后复查时，仍要尝试直接抓取。**本工具内置了零依赖直抓兜底，你可以什么都不配。**

| 优先级 | 方式 | 免费额度 | 说明 |
|---|---|---|---|
| P0 | 搜索 Provider 返回的全文 | 按对应 Provider 额度计 | LangSearch/Exa 的全文可先复用，但它是 `provider_fulltext`，不是直接 HTML/快照；不能伪装成已 `fetched` |
| P1 | 内置 httpx + trafilatura | 免费无限 | 默认直接抓取并保存快照、哈希和抓取时间；已有 SSRF、大小、超时和挑战页边界 |
| P2 | **Firecrawl Cloud** | **1000 credits/月**，无需绑卡；Scrape/Crawl/Map 每页 1 credit，Search 10 条结果 2 credits | 1000 credits 全部作为关键证据回退池；仅对已入选页面使用，且每任务最多 5 页 |

申请路径：Firecrawl https://www.firecrawl.dev/

### 5.1 进阶：自建 SearXNG（零边际成本）

- 完全免费开源，约 $6/月的 VPS 即可运行（约 200MB 内存）。
- 内置 **baidu、sogou、sogou wechat（微信公众号文章）、quark、360search、bilibili** 等中文引擎——`sogou wechat` 对舆情场景是稀缺入口。
- 部署要点：聚合 Google/Bing 需海外 VPS；JSON API 需在 `settings.yml` 的 `formats` 里加 `json` 并关闭 `limiter`。
- 风险：无 SLA，上游引擎改版/封 IP 会导致部分结果降级。
- 定位：**可选高级配置**，不作为默认。
- 来源：https://docs.searxng.org/dev/search_api.html 、https://github.com/searxng/searxng/blob/master/searx/settings.yml

## 7. 配置方法

### 7.1 两种配置入口

1. **`.env` 文件**（首次部署推荐）：复制 `.env.example` 为 `.env` 后填写。
2. **前端设置页**（部署后推荐）：配置写入本地数据库并即时生效，密钥在页面上以 `sk-***abc` 形式脱敏显示。每一项旁边有"测试连接"按钮。

### 7.3 固定顺序、换源检索与服务降级

- 系统固定按中文 `langsearch,exa,qianfan,bocha`、英文 `exa,tavily,serper` 执行，不再开放顺序调整；旧版 SQLite 或 `.env` 中的 `SEARCH_PROVIDER_ORDER` 会被忽略。某家返回空结果、结果与事件不相关、达到本地额度保护线或真实调用失败时，都会继续尝试下一家。主调查要求至少两个候选发布主体：中文依次由 LangSearch、Exa、千帆、博查补充，英文依次由 Exa、Tavily、Serper 补充；合并有效结果并按 URL 去重，达到两个候选发布主体即停止。历史对照检索不使用这条补源规则。若任务预算或单家额度上限阻止继续检索，则保留已有线索并明确覆盖不足；候选发布主体数不等于独立证据数，仍须抓取和核验。调查预算逐家计入 Provider 尝试（本地保护线拒绝的尝试也保守计入）；每次任务对千帆、博查、Tavily、Serper 分别限制为 20、10、20、10 次实际额度预留，暂停恢复后仍沿用任务计数。主题发现和调查检索中的 LangSearch 默认只取摘要以节约每日 token；Exa 全文在服务端限制长度。 调查中的明确日期范围按优先窗口处理：LangSearch 未取得合格结果时，在换源前最多用相同查询不限日期补查一次，仍执行原有事件、域名、语言和来源范围筛选；补查计入搜索预算及配额，下一家继续使用原日期参数。最近一天/一周等相对窗口及未明确允许放宽的直接调用不补查。事件记录逐次保留排除原因，界面显示“放宽日期补查”；日期元数据仍须核实。详见 [检索实测与选型边界](#11-检索实测与选型边界)。正常换源和补充不描述为 Key 失效或服务降级；只有上游调用错误、响应结构错误或熔断才属于服务降级。某一整组没有配置任何 Key 时才使用另一组保持最低检索能力，并明确按覆盖受限处理。配置多个 Provider 不等于已经完成两条独立检索路径的在线验收。
- 智谱搜索适配器只保留给旧数据和诊断代码兼容，不进入当前产品检索链，也不在设置页继续暴露。
- 同一 Provider 连续两次真实调用或响应结构失败后熔断 15 秒，到期后重新尝试；本地额度保护线和结果初筛未通过不会触发熔断。上述单任务次数仍受各 Provider 的日、月或累计本地保护线约束。
- 正文取得不是“Provider 返回全文 = 直接快照”：Provider 全文足够时先复用并保持未直抓标记；缺失或过短才用内置抓取。Firecrawl Cloud 只允许高等级、已入选的关键证据页回退，每个任务最多 5 页；主题候选发现和普通低价值页面不消耗 Cloud credits。
- 分析过程页按真实原因显示逐 Provider 路径，例如“返回 8 条但均未通过事件相关性筛选”“达到本地额度保护线，本次未调用上游接口”“调用失败后改用下一家”或“全部未找到合格材料”。历史对照查询单独标为“历史对照初筛”；通过初筛的材料仍须核验来源和案例事实，不能直接视为独立可靠案例。主题事件发现也会保存逐 Provider 诊断和覆盖受限提示。普通调查链不会把每一次换源写入最终报告，因此复核时应同时查看任务事件记录。
- 免费额度用量在本地计数，设置页逐家显示公开免费层级、本机每日和每月预留调用数、当前周期的本地保护额度及应急余量。Exa 与 LangSearch 不设本地月额度拦截：Exa 保留历史记录，按每次搜索 7 毫美元加请求全文页数（最多 10 页、每页 1 毫美元）累计月度费用估算，仅显示“本地保护：本月已记录 X 毫美元”，不显示常规或应急余量。任务整体搜索预算仍生效。调用次数从 2026-09-27 的新计数启用后开始积累，旧任务不倒填；失败的上游请求也可能占用预留，供应商实际结算和赠金余额以控制台为准。LangSearch 按成功响应记录 token，月度累计同样从新计数启用后开始；本机自然日与服务商 UTC 重置日可能不一致。本地记录不是服务商账单真值；连接测试会直接验证 Key 和上游连通，不受任务内本地保护线限制。

## 8. 热榜与历史数据来源说明

本工具的历史与热度数据分三层，**全部来自公开渠道、逐源登记许可与风险、各层独立降级**（任一层缺失不影响其他层）。说"较低风险、持续复核"而不说"全合规"——代码许可（MIT/Apache）只覆盖代码仓库本身，不等于上游平台数据的授权，这是两回事（审查修订）。

### 8.1 第一层：公开数据集（冷启动，装好就有历史可查）

| 数据集 | 内容 | 许可与使用边界（登记于数据资产表） |
|---|---|---|
| 微博热搜历史数据 | 小时级热搜榜历史，2024-05 起持续更新 | **仓库标注 MIT**（含数据文件）；MIT 是仓库作者对自己产出的许可，不等于原平台对榜单数据的再许可，仍需自行审查上游权利。只导入标题/热度/时间等非个人字段。https://github.com/lxw15337674/weibo-trending-hot-history |
| weibo16 | 16 个舆情话题数据集 | **上传页标注 Apache-2.0**——这是上传者在 HuggingFace 页面上打的标签，**不构成原始微博内容的再许可授权**；接入前须自行审查上游权利与个人信息字段（用户昵称/ID 等），导入时走字段白名单。https://huggingface.co/datasets/kuroneko5943/weibo16 |
| weibo_senti_100k | 12 万条带情感标注的微博语料 | **仓库未附明确的数据许可——默认不启用、不做一键导入、不随本项目分发**；文档仅提示用户自行评估后手动接入。https://github.com/SophonPlus/ChineseNlpCorpus |

> **一句话原则（复审修订）**：仓库或上传页上的许可证标签，只说明"贴标签的人对自己的产出怎么授权"，不能自动证明其中的第三方内容（微博正文、用户信息）可以被再分发。因此本表统一写成"标注为 X，仍需审查上游权利与个人信息"，不写"可用"。

一键导入脚本会做**字段白名单过滤**：只保留标题、热度、时间、URL 等非个人信息字段，不导入用户 ID、昵称、头像。每个数据集在数据资产登记表登记：原始来源、采集方式、数据许可、可否再分发、个人信息字段、删除机制（SPEC §6.1）。

### 8.2 第二层：热榜快照（运行时积累，越用越厚）

- 采用 **DailyHotApi**（https://github.com/imsyy/DailyHotApi ，4k★）的热榜聚合模式，定时抓取各平台公开热榜并存入本地 SQLite。
- **许可与风险如实说明（审查修订）**：其 **MIT 许可只覆盖代码**（可自部署、可修改）；README 自己声明**"仅供技术研究和开发测试"**，并说明"部分接口使用页面爬虫、未与信息提供方建立合作、信息合法性由使用者自行判断"。因此热榜数据按**低风险但非零风险**对待：只存标题/排名/热度/时间/URL 等非个人字段、控制采集频率、不对外公开再分发原始榜单数据、任一平台提出异议即停用对应源。**任何对外材料都不得把"MIT 许可"当作数据合规背书。**
- **建议自部署**（Docker 一条命令）或配置多个实例，不要长期依赖单一第三方公共实例。
- 能拿到：各平台热搜榜单、排名、热度值、话题。**拿不到**：单条帖子的评论与精确传播链路。

### 8.3 第三层：搜索 API 时间回溯（按需深度查询）

用搜索 API 的时间过滤参数（如智谱 `oneYear`）查询历史报道，覆盖前两层之外的深度需求。这是 V1 阶段"历史对照"板块的主要数据来源。

### 8.4 为什么不自建爬虫抓微博/抖音/小红书？

这是一个被认真评估过并否决的方案，原因如实告诉你：

1. **法律风险有直接对标判例**：微博诉蚁坊"鹰击"舆情系统案（(2019)京73民终3789号），一家舆情监测工具提供商败诉，**判赔经济损失 500 万 + 合理开支 28 万**。准确地说（审查修订，复审再次收紧）：法院**并未一概禁止对公开数据的合法收集利用**，而是逐案审查行为本身；蚁坊输在**手段无法证明正当、涉及需登录态等非公开数据、改变了平台的数据展示规则、与平台授权的舆情服务形成商业替代**。而"提前爬一个月社媒历史库"恰好会踩中同类风险因素：所需的评论与搜索数据要登录态（超出真正公开的范畴）、规模化持续抓取、本地囤积再展示。
   > 这段是对公开案例要旨的概括，**不是判决书原话**——"平台应容忍""加重服务器负担"等表述未经裁判文书原文核对，不在本文档使用，也不要在答辩或对外材料里当法院原话引。
2. **官方 API 对个人开发者基本关闭**：微博 Search API 仅对合作方开放；抖音自 2024 年起数据类接口要求企业认证；小红书/快手偏电商企业场景；知乎无正规开放 API；B 站不对个人认证。
3. **技术上要挂真实账号**：舆情所需的搜索、评论数据几乎都需要登录态 Cookie，会累积封号风险，且 Cookie 频繁失效需长期维护。
4. **无法随开源产品分发**：预先囤的库会包含大量他人个人信息，对外分发缺乏合法性基础——个人信息的处理与再提供需要单独的法律依据（告知同意或其他法定情形），开源分发场景下实际上无法满足。这不是"分发即入罪"的绝对判断，而是"这条路走不通、别把项目建在上面"。

因此本工具**默认只碰公开数据与公开榜单，不抓取需要登录的内容，不采集个人身份信息与关系链**。

> **可选插件说明**：未来版本（V2）会提供"用户自带 Cookie 的深度评论采集"插件，**默认关闭、需手动开启、风险自担**，且不作为任何核心功能的依赖。是否使用由你自己判断。

## 9. 常见问题

**Q：我一个搜索 key 都不想申请，行吗？**
不行。至少需要一个搜索 key（推荐免费的 LangSearch，邮箱注册即可）。没有搜索能力，本工具的证据库是空的，产出的报告没有意义。

**Q：为什么分析页显示换用了另一家搜索服务？**
先看逐 Provider 原因：返回结果但均不相关或返回空结果属于正常换源；达到本地保护线表示系统主动保留额度，本次没有调用该上游；只有明确的调用错误、非法响应或熔断才属于服务降级。设置页会显示本地已用量与保护线，连接测试则单独验证 Key 和上游连通。两者均不能替代 Provider 控制台的真实账单与额度。

**Q：为什么某些图表没出来，只有一段文字？**
本工具有一条硬规则：**算不出真实数据就不画图**，绝不画示意图充数。证据条数太少或时间跨度太短时，图表会降级为文字说明并在局限性声明里记一条。

**Q：为什么建议我配两个不同厂商的模型？**
核验环节要拿"和写报告的模型不同的模型"去逐条比对引用原文。同一个模型自己核验自己，容易把自己的错误一起确认下来。只配一个模型也能跑，但报告会自动标注"核验强度降低"。

**Q：搜索结果已经有全文，为什么还要抓取？**
Provider 返回的全文属于 `provider_fulltext`，可以用于筛选、阅读和要点转述，但不是系统从目标 URL 保存的直接快照，不能自动满足逐字引用、哈希和日后复查要求。它达到正文质量门槛时不再重复直抓；否则先尝试内置抓取。只有来源等级不高于 L3 且角色为权威、当事方或独立来源的已入选材料，才可在内置抓取失败、正文为空、遇到挑战页或 PDF 解析失败时回退 Firecrawl Cloud；每个任务最多 5 页。

**Q：免费额度会不会突然没了？**
会。各家政策和账户等级都可能变化：LangSearch 按账户 token/RPS/TPM/TPD 限制，千帆公开页面存在额度冲突，Exa、Tavily、Serper 和 Firecrawl 的免费额度也以控制台/官网为准。本文数字按 2026-09-22 的官方页面核对，**接入前仍请复核**。

## 10. 数据核实说明与残留不确定项

本文数据核实于 **2026-09-22**，优先采用官网/官方 API 文档，无法由公开页面确认的内容明确标为不确定。已纠正以下旧口径：

- **LangSearch** 不再写成“1 QPS / 60 QPM / 1000 QPD”。当前官方限制页说明按输入/输出 token 计量，受 RPS、TPM、TPD 限制，新账户公开默认从 5 RPS 起；TPM/TPD 的实际数值和当日用量在 Dashboard 查看，每日 token 额度按 UTC 00:00 重置。
- **百度千帆 Web Search** 专用 API 页写每月免费 1500 次、按天发放；其他官方页面对百度 AI Search v2 的每日额度有冲突。因此本文和配置保护按 50 次/日、1500 次/月的保守值，不把智能搜索生成接口的试用额度套用到 Web Search。
- **Exa** 是注册 $20 credits、之后每月 $10 credits；Search 基础价格 $7/1000 次，Contents $1/1000 页。不能写成 $210/月或“无限免费”。
- **Tavily** 免费层为每月 1000 credits，无需信用卡；**Serper** 的 2500 次免费额度是一次性，不是每月；**Firecrawl Cloud** 免费层为每月 1000 credits，按页面/功能计费。

以下几项仍应在接入前自行复核：

1. 博查资源包的账号资格、有效期、QPS/QPM/QPD 与长期标准价格；体验包不能代表生产价格。
2. Exa、Tavily、Serper、Firecrawl Cloud 在你的部署机上的 DNS/TLS、持续请求成功率和中文检索覆盖；官网不等于中国大陆稳定直连承诺。
3. 秘塔当前额度与全文接口；本指南不再把它放进默认抓取链。
4. 智谱搜索是否有面向新用户的免费活动；它仍可手工配置，但不在新的默认国内/国外链中。

## 11. 检索实测与选型边界

本节合并 2026-09-22 选型复审、09-23 搜索诊断及 09-28 LangSearch 真实探针中的有效结论。2026-09-30 删除了历史单独文档及原始诊断 JSON、临时脚本和验收副本；以下是原记录摘要，本次没有重新调用 Provider 或核查价格，不能把摘要当作仍可逐项回查的原始响应。

### 选型与证据形态

- 中文优先使用 LangSearch，再由 Exa 补充，最后才消耗千帆/博查有限池；英文使用 Exa、Tavily、Serper。候选发布主体达到两个只是检索补源停止条件，不是事实核验已获得两个独立来源。当前每任务额度预留上限为千帆 20、博查 10、Tavily 20、Serper 10，暂停恢复保留计数；09-23 记录中的 3/1/2/1 是旧上限，不作为当前配置。
- 搜索响应的正文按 `provider_fulltext` 保存来源、字符数与哈希，不虚构系统直接取得了目标页；可筛选和转述，不能自动用于逐字引述。合格全文可减少重复抓取，关键缺失材料才走内置直抓及有限 Firecrawl Cloud 回退。内置 Fake-IP、SSRF、正文/空壳页面和日期提取守卫不能为提高命中率而绕过。
- Exa 默认只请求一种内容视图并限制长度，Search 和 Contents 的计量分开；不要把赠送 credits 换算成无限搜索。价格、免费池、千帆不同官网页面的额度冲突及博查体验包资格，以本文原核查日和控制台为边界。
- 博查与 LangSearch 的重排组件有关联，不足以证明共享或独立的网页索引。自托管 Firecrawl 未在本项目验收；国内部署机的单次 DNS/TLS 成功和官方能力说明不能替代有 Key、连续请求及固定查询集的质量验证。09-22 新增 Provider 当时主要通过离线契约，除 LangSearch 字段探针外，不能称当时已有真实搜索质量验收。

### LangSearch 日期与召回复验

09-23 对单个中文事件的查询曾出现 LangSearch 0/8、Exa 8/8 通过事件初筛；随后六种检索词的 LangSearch 前八条中，相关数为 1、1、2、1、2、1，主要重复于两篇报道。这些是不同查询的局部结果，不能写成稳定 0/8 或服务平均质量。历史案例检索曾被错误要求包含当前事件主体，16 条候选因此被 `subject_mismatch` 拒绝；已修复独立历史案例范围，不能把这一旧筛选错误归咎于 Provider 召回。

09-28 用“武汉大学图书馆 事件 校方通报 处分决定”、`count=8`、2023-01-01 至 2026-01-01、国内范围和摘要模式真实复现 8 条均不符主体。短查询、全文模式、自然语言、无日期、扩大 40 条及限定国内域名均未补出合格国内材料；没有将这些无效改写或全量扩容作为产品默认策略。该实验确认该事件的召回不足，无法由外部响应确定是索引、分词还是排序问题。

[联合早报原页面](https://www.zaobao.com.sg/realtime/china/story20250920-7542952)当时显示 2025-09-20 10:28，LangSearch 同 URL 返回 `datePublished=2026-08-18T05:52:03Z`。因此上游日期过滤可能漏掉线索，但不能推断错误日期来自抓取或更新时间，也不能用 URL 日期覆盖权威 `published_at`。日期补查仅在调用方明确允许优先窗口回退时启用一次 `noLimit`，仍执行事件、语言、域名和国内范围筛选，并计预算/配额；下一家保留原日期。严格日期、相对时间窗口和普通直接调用不自动放宽。
