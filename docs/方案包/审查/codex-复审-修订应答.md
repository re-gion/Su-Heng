**一处与建议不同的取舍**：复审建议"执行摘要句子只能直接引用确定性生成的 claim.text，或建立可验证的摘要蕴含关系"。逐字等于 `claim.text` 会让摘要读起来像 SQL 结果集，因此取后者——蕴含校验。代价是每句一次 `verifier` 调用（执行摘要通常 ≤10 句），已在预算表里单列子额度（standard 12 次）。

### P0-2 核验输出无法区分"未提及"与"明确否定"

**接受，按建议改结构化枚举。**

- 逐证据关系改五值 `support / partial / contradict / not_mentioned / conflict`（05 §4.1.1）；`not_mentioned` 是零信号、直接丢弃，`contradict` 才进否定集。
- `claim_evidence` 增列 `relation` / `verify_reason` / `cited_sentence` / `cited_verified` / `is_correction` / `superseded`，全部落 CHECK（02 §6）。
- `cited_sentence` 必须在入模材料片段中精确子串匹配，不过则整条重跑一次；二次不过该证据关系记 `null` → claim 落 `verification_incomplete`。
- 核验器提示词第 3 条重写，明确"这两者在系统里走完全不同的分支"，并在规则 7 补一句"不要为了保守把'材料没提'写成 contradict——那不是保守，那是造一条不存在的反证"。
- 金样例 G（三家媒体全 `not_mentioned`）专门覆盖这个方向。
- 01 §4.4/§5.3 的核验结论行同步改为五值。

### P0-3 七条徽章规则可在已知矛盾存在时仍判"已证实"

**接受，改成全量决策表。**

三步走（05 §4.3）：**归并主体立场 → 计数 → 查表**。

- 第一步解决"同一主体的两条相反材料被当成两个独立信号"：按 `publisher_entity` 归并，同主体同时有 support 与 contradict 时先试**时序覆盖**（四条件全满足才成立：同主体、发布时间可比且间隔 ≥24h、该主体是 authority、后发材料明示为更正/撤回），覆盖不成立即 `self_conflict`。
- 第三步 D1–D11 决策表，D1 是"存在未核验证据"的前置闸门。
- **已用脚本验证**：100 组合法组合（`ind_S`×`ind_U`×`has_conflict`×`authority_S`×`authority_U`×`verification_complete`）**每组恰好命中一行**，且**不存在"有反证或内部矛盾却判 verified"的组合**。
- 金样例扩到 A–H 八组，D/E/F/G/H 五组分别打在复审点名的漏洞上（同主体前后矛盾、无更正声明、conflict+双支持、全 not_mentioned、核验未完成）。

### P0-4 抓取状态与引述完整性仍可写入不可能状态

**接受，两处都改：写入期拒绝 + DDL 条件 CHECK。**

- **取消"verbatim 校验失败自动降级为 paraphrase"**（05 §0.3、01 §4.4、05 §1.4 agent 提示词）。理由写进文档：那等于把一段模型编造的、声称来自原文的文字换个标签留在报告里，读者照样当成这篇来源的说法。
- snippet 增加与 `evidence.snippet` 的规范化等值校验（去首尾空白、全半角统一、折叠连续空白），不等值拒绝写入。
- paraphrase 不做字面校验，但渲染期要求该 `(claim, evidence)` 已有核验关系且不是 `not_mentioned`（R9）。
- 四条条件不变量落 DDL `CHECK`（02 §6）：`fetched` ⇒ 正文+快照+hash+时间齐全；非 `fetched` ⇒ 必须有 snippet；`verbatim` ⇒ 偏移非空且 `quote_verified=1`；fact/rumor 附加字段不得串用。另加 `is_key=0 ⇒ is_key_reason` 非空。
- **已实测**：把 02 §6 的 SQL 原样在 SQLite 内存库执行（11 张表建成），复审点名的三种非法记录 + 另外五种（非法 event_type、非法 task_state.status、rumor 带 rumor_text、is_key=0 无理由、verbatim 未校验）**共 8 种全部被拒绝**，两种合法记录正常接受。

## 五、复审"风险备忘"三条的态度

复审在销项之外列了三条不计入销项的风险，这里明确回应：

1. **M0 不砍范围、两道门只在真的肯停下来时有效** —— 认同，不做文档层面的加固（再写一句"必须认真执行"没有意义）。已做的是把两道门的判据尽量变成客观量：准确性门是"20 条人工抽检、徽章方向错误 >1 条即不过"，编排复评门是"实测代码行数、恢复/取消故障、调试时间"。是否真的执行属于项目纪律，不属于文档能解决的问题。
2. **单 HTML 不含完整快照** —— 已是用户拍板的产品边界，文档三处（01 §3.4、03 V15-5、05 §2.3/§3.9/§3.10）口径一致，且明确"对外文案不得宣称单文件包含完整证据存档"。本轮未改。
3. **摘要互证可判绿的安全性依赖 publisher 归并与截断/矛盾规则** —— 本轮的 P0-2/P0-3/P1-6 正好是在补这三处：结构化关系让反证可靠可辨、决策表让任何反证都能否掉绿标、claim 原子核验让"没验完就判绿"不可能发生。归并本身（同集团/一稿多站识别）仍是实现期的质量问题，已在 02 §6 设计说明 2 写明"未能识别采编主体时退化为可注册域名"这一保守回退。
