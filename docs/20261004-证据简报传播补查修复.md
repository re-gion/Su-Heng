# 证据简报的原稿补查修复

记录日期：2026-10-04。诊断任务：`t_20261004_6d7257b8`，标准模式、公开事件范围、评论关闭。

原报告的唯一核心发布缺项为 `media_propagation`。事实、事件时间线、执行摘要和有依据的建议已通过检查；最终范围审查没有未完成条目。历史席收到上游 `400 / 1301 / content_restriction`，但历史章节不单独阻断完整专报。

## 原因

已保存的新华网网页明确署名“来源：武汉大学官网”，却没有取得对应官网原稿。首次核心报告组装后，任务已使用73/75次搜索调用；补查未取得原稿，最后用完搜索额度。模型的反思曾声称传播要求已经满足，最终发布门仍正确拒绝：结构化关系与独立关系恢复都没有合格边，不能以模型自评替代审查。

对应[官网情况通报](https://www.whu.edu.cn/info/5231/258444.htm)的标题只有“情况通报”，正文没有“图书馆”检索词。原有关键词检查会把这份被明确署名的原稿判为 `event_mismatch`。此外，有界报告输入中的普通主体名称匹配候选可能占满原稿名额，导致新取得的原稿没有进入独立关系审查。

累计消耗1,238,839 token时，任务虽未达到140万总上限，但90%核验阶段剩余仅21,161，低于下一轮30,000的预留检查。旧代码仍空跑两轮并记为无进展；修复后明确记为预算不足。

## 修改

- 标准、深入主调查在现有搜索和抓取总额中，各预留至多6次给核心补查；不足60次的小预算按10%预留。快速档总额和主调查分配保持原规则。阶段额度与任务总额分别说明。
- 首次成稿前，依据已抓取、范围内、带可信日期的署名材料，查找具体发布主体、文书标题和发布日期。每次最多三个目标、每个目标最多两次Provider尝试、最多抓取三个候选页，仍受任务总额限制。普通媒体转载不会因标题提到机构而冒充该机构原稿。
- 泛称通报候选先保持待确认状态，再按目标网页正文重新检查主题、语言、来源范围和日期。仅因事件检索词缺失而被排除的原稿，还须满足同日发布、对应发布主体、明确来源署名，以及不少于500字且覆盖较短正文85%的连续对应片段，才补记事件关联依据。记录两份快照摘要供回查；不是事实核验结论或转载关系批准。
- 报告输入优先纳入有对应依据且两端快照未变化的原稿。转载、回应或跟进边继续要求连续来源原话和独立语义审查，审查拒绝仍交付证据简报。
- 原稿查找保存目标检查点，续跑不会反复消费同一个目标。停止后不继续抓取；搜索失败保留此前材料、诊断和警告。日期、范围状态变化计入材料进展，避免漏掉需要重新组装的变化。
- 补查阶段不足30,000 token预留时停止，保留已经审查的报告与真实缺项；不把没有发出的调用记成证据无进展。

## 验证与边界

回归覆盖：泛称通报召回及正文关联、原稿输入优先、镜像转载过滤与Provider接续、重复续跑、主调查与总预算边界、错误正文、不同日期、无可信日期、境外来源、独立审查拒绝、用户停止与搜索失败隔离。拒绝关系的夹具仍输出 `evidence_brief / media_propagation`。

同材料独立副本使用内置抓取器实际取得官网原稿，解析发布时间为 `2025-09-20T08:53:00`，建立与原任务E001的对应依据，并确认原稿进入传播关系输入。此项原稿URL查找使用固定夹具，模型调用为零；不能据此宣称真实搜索链或完整专报生成已验收。源任务、报告、证据、陈述、检查点、事件与审查调用记录在验证前后按内容摘要一致。副本、网页快照及执行结果只保存在忽略的 `backend/tmp-runtime/`。

另在一份新建副本中使用本机现有配置的真实搜索链，执行6次搜索调用、1次原文抓取，自动找到同一官网原稿，主题关联通过并进入传播关系输入，未出现补查异常。这项检查没有固定原稿URL或替换搜索服务，模型调用仍为零；源报告内容摘要不变。两个副本的检索与抓取消耗分别记录，不把它们算成一次新的完整调查。

后端565项测试通过；Ruff检查、格式检查及单向依赖检查通过。前端30项测试、类型检查及生产构建通过。三份相关文档的本地链接和Git空白检查通过。本地8000端口健康检查为正常，相关Uvicorn进程启用了自动重载；健康检查不代表新模型任务已完成。

尚未重新执行真实模型的发布关系审查或生成完整新报告，也没有跑新任务的完整搜索、调查、核验与成稿流程。原任务和原报告不自动改写。服务重新加载后，新任务使用本次修复；真实证据或审查不足时仍须降级。
