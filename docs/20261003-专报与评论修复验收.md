# 专报与评论修复验收

记录日期：2026-10-04。测试任务：`t_20261003_96d69f13`，标准模式、智能选帖、公开事件范围。

本轮修复共用编排、抓取、报告合并与评论速读路径。原任务保持不变；独立副本取得完整专报，并交付实际可读的评论摘要。评论全量处理仍未通过验收，不能宣称已稳定省费或保证每个新任务都会生成完整专报。

## 原因及修改

原报告仅缺 `media_propagation`：媒体发表节点已有，但候选引用关系没有通过独立审查。模型所见正文漏掉网页来源署名，也缺少被明确点名的原稿。报告核心初次成稿后已消耗1,118,115 token，评论处理将累计消耗推至1,373,986，之后核心恢复因预留不足停止。评论同时出现长推理、输出截断、结构无效及预算跳过；最终35条观察没有形成任何问题摘要，页面又默认折叠这些观察。

- 核心缺口恢复在可选评论之前执行，沿用原任务累计预算、证据核验和发布门。评论完成后只合并独立审查的增量，不重新生成事实、摘要或建议章节。
- 直接抓取保留可见来源署名；来源上下文采用有界连续窗口，包含正文后部署名和被点名原稿。机构别名只用于召回候选。共有原文帮助识别具体原稿，不能单独证明引用；来源原话仍须连续匹配且经过独立审查。传播审查版本参与缓存指纹。
- 识别文章标题后、来源旁的中文年月日时间；不将侧栏或正文事件日期当作发布日期。直接抓取成功后更新正文来源标记及署名，没有署名的新快照会清除旧署名。
- 单条速读索引格式错误不清空整批有效候选；保留逐项语义、隐私审查。问题归纳同时生成短摘要，多问题独立批量复核，减少逐问题重复生成。GLM兼容模型的隐私审查明确使用high档、充足且有界的输出额度；规则不变。
- 为问题摘要和审查预留剩余额度的40%，最多40,000 token，不增加总上限。续跑新增索引时，原有已审问题继续对应原来的不变样本，只有扩大后的问题通过审查才替换旧摘要。已经完成审查的结果不会因为下一次调用额度不足而丢失。
- 无合格问题时默认展开已审关切；有问题时展示摘要、代表原话，保留全部关联原话与关键词搜索。

## 同材料真实验收
