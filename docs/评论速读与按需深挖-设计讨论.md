# 轻量评论功能设计探索

更新日期：2026-10-03。状态：整体方案与实施、真实验收范围已获用户确认。核心功能已实现，在线验收记录与完成度见[实施与验收](评论速读-实施与验收.md)，当前自动全量速读和省费目标尚未通过。

## 已确认的取舍

1. 默认交付“评论速读”，整理具体关切、不同理由与诉求，保留原话回查；证据对照和处置建议按需深挖。
2. 每条合格评论建立简短的问题、理由、诉求索引，在问题层生成摘要并配代表原话；取消默认逐条生成完整长篇观察。
3. 沿用此前确认的具体问题组织、复合评论可关联多个问题、原评论关联与去重计数。所有合格样本仍可回查，少数或相反观点保留，拿不准的单列待归类。
4. 按需深挖由用户点选具体问题后启动，默认先对照已有报告材料；仍有缺口时，公开补查由用户另行开启。

这调整了此前“画像与建议都要，处置优先”的默认交付方向。已经实现的深度分析可作为按需能力保留；本次已将新默认流程接入编排与任务页；此前的分层证据对照与研判作为点选能力保留。

## 从哪里节省开销

此前冻结材料验收的最终副本消耗288,808 token，最终交付198条观察、1个具体问题、1项证据对照和1项建议。它复用了前轮材料并经历续审，不能当作一次新任务的完整基准。

现有流程反复把评论改写为观察，再归纳问题、准备事件证据、形成对照、研判并审查。原话、观察和事件材料在不同阶段重复进入上下文，长篇结构化输出也容易截断。轻量方案的核心是减少默认产物和重复表达，不靠少处理样本、降低模型质量或放松审查换取效率。

真实验收已执行，但未证明在完整覆盖与相同质量下更省费。短输出仍有长推理和截断重试；不能承诺固定节省比例。具体结果见[实施与验收](评论速读-实施与验收.md)。原话浏览与精确检索不新增模型调用，新增文本仍须审查。

## 可共用材料的功能

| 功能 | 读者能得到什么 | 新增分析开销与限制 |
| --- | --- | --- |
| 已审原话检索 | 按关键词、帖子、平台或可靠时间找原评论，查看上下文和出处 | 已审材料的浏览、精确检索和计数可由程序完成；新原文仍须审查，脱敏改变或审查失效也须处理 |
| 评论速读 | 看清具体问题，以及问题下不同理由、诉求与代表原话 | 简短归属与问题摘要仍需必要语义处理和审查；不能只靠关键词判断支持、反对或讽刺 |
| 问题与诉求清单 | 看到“希望说明哪些依据”“请求公开哪些程序”等直接表达 | 可从同一合格索引派生；只表示评论提出了要求，不表示机构没有回应或要求应当采纳 |
| 相关报告材料入口 | 从一个关切跳转至报告中已有的事实、回应或来源 | 可先提供材料关联；匹配到关键词不等于已充分回答，自动回答另行审查 |
| 按需深挖 | 针对选定问题对照公开证据，必要时形成条件性风险与处置建议 | 已确认点选触发，先使用已有报告材料，公开补查另行开启；已有显式接口与任务页按钮 |

以上是能力建议，并非都已确认要开发。首版应先让评论速读和原话回查成立，其他功能只有能复用同一产物、确有价值时才加入。

## 建议的速读形态

围绕具体问题，每项展示简洁的关切摘要、不同理由或诉求、几条可回查原话，以及对应去重样本数。首屏保持简短，展开后可查看全部相关合格评论；展示篇幅限制不等于缩小分析样本范围。

例如“认可依法处理，但希望公开复核程序”可以进入处理依据和程序透明两个问题。不能把它简化为纯支持或纯反对；两个问题各关联同一原评论，整体样本仍只计一次。

问题内样本频次可用于浏览，不直接等同重要程度、真实人数或舆情风险。少数但具体的理由应保留；无法可靠归类的评论单列，不强行归入相近主题。精确重复可以折叠并披露口径，语义相似不能直接当作重复而删除。

完成状态分开呈现：原始样本审查范围、合格样本索引进度、速读摘要是否合格、按需深挖是否启动及其结果。未开启深挖时显示“未启动”，不能据此将合格速读标为分析未完成；速读摘要本身未审完则仍须标明局限。

这里的默认方式仅作用于用户已启用评论功能并确认帖子的任务，不能理解为自动开启评论采集。

## 推荐的实现取舍

本地程序承担精确去重、统计、筛选、原文链接和引用匹配；需要理解否定、复合诉求和不同理由的部分，仍使用必要的模型归纳与独立审查。纯关键词与词频方案适合作为原话浏览入口，尚不足以可靠承担“评论速读”。

默认流程只处理短索引及问题级摘要，避免为每条评论生成多段说明，再把说明重复改写。已审原话直接从保存的样本回填，模型提供引用位置；生成的摘要仍经过相应审查，不因原话合格而自动合格。代表引语用于阅读，归纳与审查的依据不能仅限被选出的几条引语。

首先实现速读和原话回查。问题、诉求清单若能从同一合格产物直接派生，可作为后续小功能；跨批次态度变化、自动风险榜和全网情绪比例不纳入这版设计。

## 审查与利用边界

- 简短索引必须关联原评论及必要语境；没有通过对应审查的生成内容不能作为正式摘要展示。
- 问题摘要及新的推断仍须来源、语义和隐私审查；摘要失败时保留仍然有效的已审原话及检索入口，不把分类完成当作分析合格。
- 已审结果仅在材料、范围、策略与输出用途仍然有效时复用。代码统计、引用匹配不能替代语义与隐私审查。
- 待审评论与被排除评论单独披露范围。此前采集600条中399条尚未完成范围审查，不能因为启用速读就当作可展示、可外发的合格材料。
- 评论中的追问、传言或质疑不能当事件事实；不能从样本外推全网态度，也不能从当前材料缺口断言机构从未回应。
- 关键词、问句或共现索引可以辅助定位，不直接证明语义立场、关切重要性或情绪变化。跨批次变化只有在采样范围和时间可比时才有讨论基础。

## 实施边界

用户已确认以“简短索引＋问题摘要＋原话回查，点选问题先对照已有材料，公开补查另开”为整体方案，进入实现与同材料真实验收。

批次大小、显示条数和缓存结构属于实现选择，可在确认产品边界后自行确定，不逐项交给用户决策。公开补查继续受原任务公共性、隐私、核验及预算限制，用户开启不等于获得额外额度。

## 后续验收标准

先用相同合格样本做对照，分别检查关切覆盖、相反与少数理由保留、复合评论归属、原话引用准确性和去重计数。此前已审观察可作对照材料，但不能当作完整人工标准答案；原评论仍是语义核对的依据。用实际调用记录比较输入与输出token、重试、主动耗时，隐私审查与分析耗时分开记录；复用验收与完整新流程验收分开汇报。

只有轻量结果通过上述质量检查，并取得真实消耗记录后，才能判断是否更经济、更快。验收使用原先冻结材料中的187条已审评论；未完成审查的399条不外发。当前运行库已无此前两条测试任务，不能将冻结材料验收写成现有库的新任务端到端验收。
