# 执行摘要：实施与验收

日期：2026-11-14。

新生成的专报默认在正文及范围审查完成后独立综合摘要，通常3—4段、600—900字；材料不足时缩短。摘要交代事件主线、当前状态、主要争议、核心判断、重要边界和后续关注。段落保留紧凑引用，原事实正文、徽章和引用卡不变。生成、内容审查或范围审查未通过时明确交付事实提要，并保留完整专报的摘要缺口。

## 实现范围

- `core/executive_summary.py`：从最终报告构建上下文，约束句子类型、引用、数字及单位、重复与内部术语，并校验审查记录是否仍对应当前内容与依据。
- `agents/reporter.py`：reporter写作、verifier批量逐句及整体审查，至多修订一次；只缓存通过内容审查的结果，不采信初稿自报通过。相同模型的角色复核保留独立性局限。
- `services/executive_summary.py`与`full_report.py`：在最终范围审查后接入摘要；保护范围下新增叙述需再过范围审查。评论增量使旧叙述摘要失效，正常流程再综合；旧版摘要不自动改写。
- `render/html.py`与`validator.py`：连续段落、紧凑句末引用、可回查研判及局限；R25拒收无效、未审或依据变化后的摘要。HTML、速览和PDF使用同一份内容。
- IR升级为0.10、最低阅读器10；旧0.1—0.9迁移保留原文字与徽章，不补造摘要。

完整字段见[核心契约](方案包/05-核心契约.md)，产品要求见[产品SPEC](方案包/01-产品SPEC.md)，运行及降级规则见[报告质量与验收](报告质量与验收.md)。

## 实际验证

1. 摘要及关联回归最终185项通过，覆盖无效引用、数字/单位越界、初稿自报通过、审查缺项或非布尔判定、正文/事实/徽章/分析/局限变更、缓存失效、同模型说明、范围改写失效、评论兼容、IR迁移和完整报告组装。
2. 本机Chrome在1440px和390px宽度下检查段落、无徽章堆叠、水平溢出及事实/研判/局限引用跳转；生产`ChromiumPdfExporter`导出与中文内容、链接检查通过。最终真实模型样例PDF为6页、50个链接注解，并生成桌面和手机截图作目视检查。
3. 使用既有配置的reporter/verifier和虚构高校诉求材料在线验证。最终版本一次生成4段664字，逐句和事件、当前状态、争议、发现、边界、后续关注六项覆盖审查通过；两次请求共6461 token。两角色使用同一模型，不能据此宣称异构交叉核验。
4. 最后一次全量后端测试710项通过、1项失败：`test_directory_scroll_is_independent_of_document[1800]`。用HEAD中修改前的渲染器复测，同一目录滚动检查在1380px和1800px均可失败，属于既有布局/时序问题。本轮未修改目录实现。全量测试之后仅补强摘要后续关注检查及研判句关联局限的规则，再执行上述185项相关回归，全部通过。
5. 后端Ruff、格式检查和import-linter通过；前端38项测试、typecheck、生产build通过；Git差异空白检查通过。SPEC、核心契约、README和质量说明已同步。

## 验证边界

在线材料是明确标识的虚构开发样例，用于验证结构、引用和实际模型调用流程；不代表武汉大学事件或其他真实复杂事件已经重新调查或验收。曾观察到上游失败、结构拒绝及修订，相关路径会明确降级，不保证每次都产出叙述摘要。现有已保存报告不自动改写；本轮不包含生产服务器部署或运行服务重启。

摘要写作及审查沿用既有模型配置和任务额度。通常新增一次写作、一次审查，必要时再修订和重审；底层传输重试仍受现有网关限额约束。哈希与结构检查只发现变化和引用错误，内容正确性仍受模型审查能力限制。
