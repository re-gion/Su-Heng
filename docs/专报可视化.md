# 专报可视化

专报优先用图解释事件经过、分歧、回应关系和行动条件。图表按当前报告中的材料生成，不设置必须凑齐的数量，也不把材料数量解释成事件热度。

## 当前可用的表达

| 表达 | 出现条件 | 阅读方式 |
| --- | --- | --- |
| 事件时间线 | 已有带明确年月日、正文和引用的本事件陈述 | 按时间阅读、切换类别分轨、筛选类别、恢复全部；点击节点查看引用。两个及以上节点的事件时间线也进入速览。 |
| 问题与依据对照 | 第 04/05 节的已审分析具备标题、观察、解释、不确定性和证据引用 | 并列展示“所据记录、解释与分歧、边界与待查”，各项可折叠；直接展示原有分析，不重新推断回应状态。 |
| 条件行动图 | 同一项建议同时具备触发条件、责任主体和行动 | 并列说明何时触发、建议由谁负责及采取什么行动。仍属于分析建议，不是机构已作承诺。 |
| 已核实的发布关系 | 至少存在一条具有有效端点、关系类型、引用和引句的已审关系 | 展示原发布与转载、回应或跟进的连接；可展开连线依据。未连线的材料保留在其他发布记录中。 |

所有可视化均在单文件 HTML 内完成，不依赖在线图表库或新增模型调用。已有报告通过当前阅读/导出接口重新渲染时，会从其已保存的本事件事实表恢复曾被数量上限或日期识别规则遗漏的节点；原报告数据、陈述正文和核验结论不变。若旧报告本身没有提取事件起点，重新显示不能凭空补出，需要重新调查、提取并核验。先前已导出的 HTML/PDF 文件不会自动变更。

## 数据与阅读边界

- 图上的事实原句、核验徽章与引用使用原有报告字段，不改变数据库判定。已有回应不等于争议已经解决。
- 时间线类别按陈述中的明确发布主体或动作作保守阅读分组，不能视为新的事实分类。各类别内部按日期排序，节点间距不表示真实时间长度；类别较多时分轨区域可横向滚动。
- 节点仅使用陈述正文明确写出的年月日，支持主体后的日期、晚间等时间修饰和主体名称中的车型数字；无效日期、模糊时点和无引用陈述不进入定时时间线。不把一条通报回顾中的多个日期自动拆成新的事实节点。需要独立事件时点时，应先补充具有证据绑定的独立陈述。
- 事件时间线保留已有的全部合格节点，不再实行“同日最多两条”或“总共十二条”的截断；重点窗口外的本事件前史和后续保留并标注。同日先后不明时并列阅读，不据列表顺序推断因果或先后。
- 阅读时按“日期、明确主体、发布动作或文件类型、内容与来源关联”保守归并同一事项：跨来源的近义复述集中为一个节点，同一文件的概述与重叠细节可集中展示。代表句取自原有陈述，不由模型改写；不同实质要点仍直接显示，全部原句、引用和各自的核验状态均可展开回查。归并节点使用“逐条核验”提示，不把某条陈述的徽章套用于整组，不增加独立信源计数。
- 不以同日、同类别或同一网页作为充分归并条件。不同数字或单位、明确的否定关系、处置动作、测试条件、文件标题、对象或已知时段分别保留；组内所有成员都要满足这些边界，避免借一条泛化概述把相互冲突的记录串到一起。无法可靠确认同一事项时保留独立节点。归并只产生阅读投影，事实表及保存的逐条时间线不被删改，旧报告重新打开即可使用；完整性检查按归并后的事件数计数。
- 事实调查覆盖最初披露、首轮回应、关键转折和当前进展；长材料摘要预留早期与后续带日期的行动段落，避免最新处置细节挤掉前史。已准入正文若提到早于现有节点的发帖、测试发布或通报等动作，新报告记入 `quality.event_chronology.earlier_candidates`，添加 `event_chronology` 发布缺口并定向补查。候选仅供补查，不能直接作为事件事实展示；受预算或证据限制未补齐时明确标注，不能通过完整专报发布门。未检测到这类缺口也不代表穷尽了事件始末。
- 分析对照沿用已审文本，不新增“已解决”“未回应”等确定性状态。未在所采材料中找到记录不能解释成现实中没有开展工作。
- 发布关系仅连接已有依据的端点；不按发布时间补连线，不推断源头、中心性或影响力。没有合格关系时保留原来的材料卡片。
- 静态、动态和不同样件的测试值不能直接合并比较。现阶段没有新增数值比较图、公众情绪占比、全网声量、地图或自动风险评分。

## 导出与无障碍

筛选和分轨只影响屏幕阅读。打印时恢复全部时间线节点，展开问题对照和连线依据，使用适合纸面的顺序布局；打印结束后恢复屏幕筛选与折叠状态。时间线在 PDF 中保留日期、陈述、核验说明和引用编号，冗长的完整引句在 HTML 节点或证据包回查，避免把整篇来源重复印进时间线。

控件提供中文标签、键盘焦点和筛选结果提示。小屏幕采用单列布局；不依赖悬停才能获取信息。关闭 JavaScript 后仍可阅读默认时间线、展开原生折叠项及使用引用锚点，筛选与布局切换需要 JavaScript。

相关回归位于 `backend/tests/unit/test_event_chronology.py`、`backend/tests/unit/test_timeline_event_grouping.py`、`backend/tests/integration/test_report_quality_pipeline.py` 和 `backend/tests/integration/test_report_visualizations.py`，覆盖起点与中段保留、日期识别、旧报告只读恢复、长材料前史保留、前史缺口触发与补齐、保守事件归并、逐条核验状态和引用保留、速览可见性、键盘展开、引用跳转、筛选重置、打印恢复和手机布局。实际事件回放仍须另外检查数据条件与版面，不能用测试通过替代真实搜索和模型验收。
