# ADR-0005: 调查席位边界与优先时间窗口

**Status**: Accepted（产品决策；具体实现与验收仍须核对）
**Date**: 2026-09-25

## Context

把用户日期范围作为主证据硬门会排除同一事件较早的起因或较晚公布的结果，也会把结束日期误当作“截至当时”的观察截止。事实席与传播席复述相同事件事实，历史席又可能把本事件旧报道当作独立案例。论坛主持人放行后的定向指令和沿用轮次编号的专项补查，进一步混淆论坛结束与报告质量门。

## Decision

1. 用户日期范围是**优先调查时间窗口**：各调查席先尽可能检索窗口内材料。为补齐本事件前史、后续结果，或为历史对照取得必要材料，可以越界；须记录并展示材料发布时间、越界原因和用途。没有设定范围时，不产生“越界”标签。需要重建“截至某日能知道什么”时须另设观察截止日，不从时间窗口终点推断。来源发布时间、事件发生时间与观察截止日分别记录；日期不明的材料不能伪称为窗口内材料。
2. 事实调查席负责**同一事件的完整事实链**，优先查官方通报、当事方一手文件和权威媒体；同一事件的早期经过及后续结果仍归事实席，即使越界。历史洞察席先查本地历史库，再按证据缺口回溯检索其他事件：有可核查直接联系的**关联前事**，与无已证实直接联系但机制相似的**类比案例**分开呈现。两类均须说明关联或相似依据、关键差异和已公开结果，不能用于证明或预测本事件的结果。
3. 媒体传播席分析可核查的新闻报道、公开原帖和视频，说明发布者、平台、发布时间、报道口径、回应和可回查的传播关系；评论洞察席仅在评论深挖启用且用户确认帖子后分析实际采集的评论样本。单次调查可描述**报道脉络**，只有同口径多时点数据才可称热度趋势。互动数必须标注获取时点与范围，不代表全网态度。
4. 论坛采用调查席轮内并行、汇合后主持人评审、必要时下一轮定向补查。主持人按席位产物和引用识别具体缺口、冲突；指令必须有明确收件席位，并只传给该席位。主持人放行或强制结束即终止论坛，不再发布下一轮指令。之后由核验发现的具体章节缺口触发有界的**章节缺口补充调查**，作为独立阶段展示，不继承论坛轮次或已放行指令。论坛放行与核验、报告发布门分别判定。

## Consequences

- 必须修订原有范围过滤、时间线、报告发布门和历史对照分类，避免继续以“窗口内主证据”作为唯一完整性条件；窗口外材料仍须通过通常的来源与陈述核验。
- 传播关系、媒体态度、评论样本和热度趋势须分别标明证据边界。缺少传播边时仍可呈现有来源的报道口径，但不得把发布时间排序伪装成传播路径。
- 论坛消息和用户界面须保留指令收件人、阶段和轮次的含义；长摘要应按要点呈现，且不得改变权威陈述正文。
