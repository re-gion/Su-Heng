# ADR-0004：区分搜索服务正文与直接快照，并用本地额度保护驱动检索降级

- 状态：已接受
- 日期：2026-09-22

## 背景

LangSearch 与 Exa 可以在搜索响应中返回正文。重复直抓每一个结果既浪费免费额度，也会增加反爬失败；但把上游正文直接标成 `fetched` 又会虚构本系统取得过目标网页响应、快照和哈希。与此同时，千帆、博查、Exa、Tavily、Serper 与 Firecrawl 的免费池有按日、按月或一次性差异，不能等到上游报错后才降级。

## 决策

1. 中文检索按 `LangSearch → Exa → 千帆 → 博查`，英文检索按 `Exa → Tavily → Serper` 路由；结果为空、过滤后为空、不可用或触及本地保护线时进入下一家。主调查的候选发布主体不足两个时也逐级补源，达到两个即停止；历史对照不使用这条补源规则。2026-09-23 的受控查询显示，Exa 对所测中文事件前 8 条有 6 条通过事件筛选，故先于额度更少的千帆、博查。
2. 搜索结果随附的长正文写入 `evidence.content_text`，并记录 `extra.content_origin=provider_fulltext`、字符数和独立哈希；记录继续保持 `fetch_status=discovered`。
3. 上游正文达到最低可用长度时不重复直抓。缺失或过短时先用内置抓取；只有来源等级不高于 L3 且角色为权威、当事方或独立来源的已入选材料，才可在挑战页、空正文、重试耗尽或 PDF 解析失败时回退 Firecrawl Cloud，每个任务最多 5 页。主题候选发现不调用 Cloud 回退。
4. `provider_fulltext` 可用于筛选、聚类、分析和非逐字转述，但不能用于 `verbatim` 引述，也不能显示为本地直接快照。
5. SQLite 按 Provider 与周期原子预留额度。常规任务只用常规池，恢复查询等关键路径可以使用应急池；LangSearch 的公开 TPM/TPD 数值未知，只记录真实响应 usage，不虚构固定日请求数。

## 结果

2026-09-28 补充：在调用方明确将日期视作优先窗口时，LangSearch 的明确日期查询如无合格结果，先用相同查询 `noLimit` 补查一次，再继续下一家。补查计入同一预算与配额，保留全部事件、域名、语言和来源筛选；下一家使用原日期范围。严格日期调用和相对时间窗口不自动放宽。每次尝试分别记录日期、补查原因和排除计数。依据与验证见 [检索实测与选型边界](../方案包/04-搜索与数据源配置指南.md#11-检索实测与选型边界)；该补查不能补齐上游缺少的国内事件材料。

- 免费搜索附带的正文可以减少重复请求，同时不破坏证据留存语义。
- 报告会同时出现“搜索服务正文（未直抓）”和“网页原文抽取”两种材料形态，原文取得率只统计后者。
- 本地保护线是成本防线，不等于服务商账单真值；开通账号后仍需用控制台核对额度。
- Firecrawl Cloud 只作为低频回退。自托管不在本决策范围内，只有隐私、出境或规模要求成立时再单独评估。
