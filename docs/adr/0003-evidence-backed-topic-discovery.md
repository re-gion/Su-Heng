# ADR-0003: 基于证据簇的主题事件发现

**Status**: Accepted

**Date**: 2026-09-21

## Context

旧实现把搜索结果标题直接当成具体事件候选，只检查标题是否含调查主体。它无法区分例行通知、导航页和真正争议，也没有把同一事件的多家报道归并；搜索 Provider 忽略域名约束或返回摘要偶然命中时，候选会明显离题。评论插件的“智能选帖”曾同时承担主题检索词扩展，导致事件发现和帖子发现边界不清。空结果只显示一句提示，用户无法判断是没有事件、时间范围过窄、Provider 失败还是过滤器拒绝。

## Decision

1. 新增独立 `TopicDiscovery` 深模块。编排器只负责预算、检查点和暂停/恢复；评论候选发现只在具体事件确认后运行。
2. 检索结果先通过主体、事件行为、语言、地域和可信日期窗口过滤，再按事件特征聚为事件簇。候选卡展示规范标题、摘要、时间跨度、来源角色、入选理由、证据缺口和原始来源。
3. 至少一个官方或当事方来源，或至少两个独立可靠来源，才满足证据确认条件。只有一条有效检索路径时一律降为待核实线索，并披露覆盖限制。
4. 用户未指定日期时，事件发现默认使用近 12 个月。空结果后只执行一次受限恢复检索；系统不静默扩大时间、语言或地域。用户可以显式把默认窗口扩到近 3 年。
5. 候选最多 5 个，按证据、相关性和影响优先于新近程度排序；界面不默认选中第一项。
6. 手工事件必须先做轻量来源预检。预检失败后允许修改，或由用户明确强制继续；强制继续仅可生成 `retrieval_diagnostic`，不能越过完整报告发布门。
7. 所有检索尝试记录轮次、查询词、Provider、原始命中、接受数量、拒绝原因和错误，空结果也必须可诊断。

## Consequences

- 宽泛主题会多一个可解释的人工确认步骤，但不再把搜索标题或例行通知直接冒充事件。
- 单 Provider 部署仍能工作，但候选会明确降级；要获得完整覆盖说明，需要至少两条独立检索路径。
- 默认时间窗口会减少过时事件干扰；扩大到三年必须由用户操作，并传递到后续调查。
- 事件发现与评论选帖各自可测试、替换和演进，避免一个提示词同时承担两个领域职责。
- 事件聚类是确定性启发式，仍可能拆散或合并边界模糊的事件；最终选择继续保留人工确认。
