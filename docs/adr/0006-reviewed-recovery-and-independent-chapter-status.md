# ADR-0006：以已审报告驱动补查，分开调查结束与报告定级

日期：2026-09-26。状态：已采纳。

## 背景

两次标准任务在两轮协作后结束，主持人仍有高优先级缺口，总 token 尚未耗尽。传播补查依据未审候选，最终审查后却没有有效关系。历史和评论失败被额外用于降低整份报告等级，批量审查异常还会丢失其他独立条目的成果。

## 决策

1. 保留标准模式总预算和两轮协作讨论；核验和初次组装后，按最终核心缺口进入专项补查。优先事实与传播，再处理可选章节。补查陈述重新核验，传播关系使用同一份审查结果驱动补查与发布门。
2. 核心条件达成、连续两次无有效进展、预算不足或用户停止时结束；暂停保留检查点。主持人批准结束讨论不直接批准完整专报，讨论上限不等于强制放行。
3. 完整专报要求具体事件、主证据、关键陈述、事件时间线、合格传播关系、完整摘要和有证据的行动建议。历史、评论单独显示完成度，缺失不单独阻断完整专报。本决策明确 ADR-0002 的发布标签，并补充讨论结束后的恢复流程。
4. 评论检查点版本为 2，保存样本指纹、逐条分类、主题成员、待审主题、已审主题和历史警告。单批或单主题异常不阻断其他独立内容。样本改变或旧字段不足时说明重做阶段。没有合格主题时不称分析完成；全部样本无关时可以完成分类并如实显示零个相关主题。
5. 传播候选、拒绝和调用异常单独记录。仅保留已审且两端及支撑来源未变化的有效关系，旧的未经审查候选不能恢复为有效边。
6. HTTP 诊断保存状态、经过格式约束的错误码、原因类别、简短说明、阶段和批次，不保存上游全文或原始请求。不能确定的 400 原因记为 unknown。请求和截断重试分别计数；已返回响应按 usage 计费，缺少 usage 时保守估算。失败请求未返回 usage 时无法确认上游实际计费。
7. IR 升为 0.7，reader minor 为 7。新增章节状态和结束说明；旧报告读取迁移只补 unknown，不补造分析或改变旧发布等级。HTML、PDF和证据包保持同一 IR 语义。
8. 产品命名“溯衡 · 舆情调查与研判”，采用浅色工作台。删除首页本地库零值统计及专用请求，保留后台数据功能。讨论按轮次和角色分组，专项补查另列；配置显示中文角色并保留内部键名。
9. 总 token 上限不变，网关使用同一个累计计数。主调查的调用上限为总额的 60%，初次独立核验可用至总额的 90%，报告与已审缺口补查使用余量。未用完的前阶段额度自然留给后阶段；主调查达到阶段上限时明确记录原因，余额不足以支撑补查、核验和报告重建时保留当前已审报告。
10. 报告优先生成行动建议，再顺序生成传播、观点和历史分析；每章只接收有界事实与关联来源。传播关系审查除已有媒体陈述节点，还可纳入范围内、已抓取、带明确来源标注的发布页及被点名的原稿。新节点只有在关系原话检查和独立审查均通过后才进入传播图。电子报版面脚本中的日期须与当前文章 URL 的版面日期一致，才可作为网页日期，并保存日期来源；仅有检索提供的日期不能据此越过范围门。
11. 已有事实得到一份独立来源支持但未达关键事实门时，可以从本任务已抓取、日期确认、调查范围内的不同发布主体原文中寻找第二份佐证。文本重合只决定候选顺序；逐证据关系和最终徽章仍由原核验链确定。每个任务最多补审三组关系，并沿用核验阶段和全局 token 上限。检查点记录已试组合，续跑不重复消耗同一组合。
12. 模型引用的字符与原文一致但省略了版面换行或空格时，核验器定位原文连续片段并保存原文形式；其他字面差异仍拒绝该关系。时间线接受句首日期，或具名机构后紧接日期与公开动作的陈述；只使用已完成核验的本事件陈述，不将网页发布日期当事件日期。
13. 报告模型只看到的来源预览属于内部输入边界，不得在面向用户的分析与行动中写成网页抓取状态或要求外部机构核对“本报告预览”。编辑审查还需核对事件先后，避免把后来才作出的裁判倒推为与早期机构决定长期并存；已发布旧报告保留原文，新规则仅用于后续生成。

## 影响与边界

2026-09-27 修订：真实标准任务反复触及调查阶段 token 预留，标准档总预算由 75 万提高到 90 万；60%/90% 阶段比例不变。其他阈值和快速、深入档暂不调整。报告将普通单源且有完整原文直接支持的待核验陈述标出证据强度，不改变 D8 裁判性官方单源例外、数据库徽章或发布门。同一历史案例的多条陈述合并为一张案例卡，保留全部引用。免费层级只展示公开参考值，本机日/月使用量与服务商账户余额明确区分。

2026-09-27 后续修订：两次新的标准任务分别耗用 84.5 万与 86.9 万 token，均用尽 45 次原文抓取额度；三档默认总预算现为 30/140/200 万 token，检索与原文抓取额度同步提高，60%/90% 阶段预留不变。原网页日期识别覆盖已保存案例页中明确标注的文章发布时间和目标页自带的 `pubtime_baidu` 文章时间字段；仅搜索服务提供的日期仍只是待核实历史案例线索，不进入正式对照。媒体发布关系的候选输入增加“据某媒体消息／报道”的明确署名稿件，但有向关系仍须原话匹配和独立审查。模型返回 `finish_reason=length` 时在更高但有限的输出上限内重试，报告章节再次截断则用缩短的输入重试一次，仍不完整时保留章节缺口。上述调整不追改已发布报告，历史案例与报告分析仍须通过原有核验和发布门。

标准模式可能在两轮之后继续运行，仍受调整后的总预算约束。阶段预算会在接近预留线时停止新增调查，保留独立核验和报告成稿额度；不能把阶段预算结束解释为证据已充分。外部材料不足仍可能只形成证据简报，深入模式不保证通过。可选章节失败仍会披露，并可触发一次有限补查。原任务和原报告不自动重写；新评论采集仍需确认帖子和登录。

2026-09-27 复验边界：在原任务数据库的**独立副本**上，无智能选帖任务 `t_20260927_9495549c` 的在线报告层重放得到 `full_report`，发布门无缺项；对其已保存的 E031/E032/E033 原网页重新识别日期，历史层独立重放形成 1 张案例卡。智能选帖任务 `t_20260927_4921ba5d` 的原样报告层重放仍为 `evidence_brief`，缺 `media_propagation`；对其已保存的 E013 原网页识别出 `pubtime_baidu`，按既有范围规则在副本中重新判为主证据后，在线报告层重放得到 1 条独立审查接受的新华社消息引用关系，报告成为 `full_report`，IR 校验无错误，发布门无缺项。上述重放复用了原任务已取证据和陈述，不等同于按新预算完成一次全新端到端调查，也未改写源数据库或已发布报告。
