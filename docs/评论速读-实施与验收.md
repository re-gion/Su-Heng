# 评论速读实施与验收

最新修复记录见[专报与评论修复验收](20261003-专报与评论修复验收.md)：新测试的独立副本恢复完整专报，交付8个摘要、59条短索引和125条原话。评论全量处理仍未完成。以下保留此前187条冻结材料的历史验收，不能与新任务混用计数。

日期：2026-10-03。用户确认实施及同材料真实验收，允许推送。结论：核心功能已实现，浏览与检索可用；自动全量速读、稳定省费和这批材料的点选深挖尚未验收通过。

## 实际交付

- 默认短索引、具体问题摘要、代表原话；展开全部关联原话、待归类的已审索引，关键词搜索全部合格样本。浏览、展开、检索只读本地材料，不新增模型调用。
- 来源、语义、隐私审查分别约束交付；复合评论可拆分，统计对原评论去重。无明确布尔审查判定的结果不发布，建议失败不清空已审索引。
- 显式点选“对照已有材料”，有公共可查缺口后另点“开启公开补查”。继承原任务累计预算，每任务单飞，下线复核及容器、Demo禁用。模型预算不足保留原报告。
- 缓存绑定样本、范围、策略及材料；新增无关索引不重组有效旧问题。新的关联改变问题内容时仅重审依赖摘要，公开材料变化后旧证据回答失效。成功深挖同步恢复检查点。
- 模型调用记录独立统计推理档及采样参数，输出预算按档位隔离；隐私和深挖调用保留原设置。

## 真实模型结果与边界

使用原先冻结材料中的187条最终已审评论，保留原评论、帖子和证据关联。采集600条中的399条待审评论未发给模型；9条重复或空文本、2条范围排除、3条最终隐藏也不作为本次合格样本。没有重采评论，没有覆盖当前运行库。当前运行库已经没有早先两条测试任务，保护校验对象是含这两条任务的冻结档案，不能写成现有原任务在线验收。

模型采用现有tierflow.cn配置的GLM-5.3-FlashX，生成与复核来自同一模型服务；独立调用审查不代表异构交叉核验。每个验收副本最多新增30万token，续跑继承累计消耗；运行时数据库、报告、评论和调用记录保存在本机，不进入Git。

最后一轮交付187条可回查原话、140条已审短索引（覆盖139条不同评论）、4个问题摘要（覆盖87条不同评论）；168条已分类，22条无关，19条尚未分类。53条索引尚未进入合格问题，7条相关样本尚无合格索引。以上计数由程序计算，问题与立场的样本数不能相加，不代表真实参与人数或总体民意。

该轮速读累计分析用量250,220 token，交付累计用量250,776 token，均扣除先前点选尝试的33,043 token；加回点选尝试后总量283,819。续跑耗时79.58秒只属于追加阶段，不能冒充整轮耗时；完整运行还包括此前模型服务故障及等待。token是服务返回用量，未换算为人民币或服务商实际账单。

本轮四个独立验收副本累计新增1,075,852 token（238,317＋267,589＋286,127＋283,819）。单副本上限均为30万token，但它不是本轮所有实验合计上限；失败尝试全部纳入累计，不能只披露最后一个副本的28.38万。

此前深度流程的288,808 token副本复用了前轮材料并经历续审，覆盖及产物也不同。不能据此声称本次节省固定百分比。实测表明短输出仍可能伴随长推理和截断重试；请求简短推理档不保证低消耗，官方推荐采样参数也未使本批材料完成全量分析。见[官方模型说明](https://docs.z.ai/guides/vlm/glm-5.3-flash)。

冻结档案在最后两轮执行前后按两条任务的任务、报告、陈述、证据及评论记录计算摘要，均一致。第一轮曾查询已无旧任务的当前库，得到空集合摘要，该结果不能证明原任务未变；已纠正本机记录。第二轮因异常退出未完成末尾摘要比对，不将其写成保护验证通过。

## 使用建议与未完成事项

当前可靠的轻量价值是已审原话检索、问题和短索引浏览，以及显式控制深挖；评论功能仍为实验性能力，默认采集关闭。自动速读依然会产生明显模型费用，不能作为已证明省费的功能宣传。正常新任务沿用自身总预算，不能把这次独立副本的30万上限理解为重置原任务额度。

未完成：本批合格样本的全量速读、全部索引的问题归属和真实点选深挖成功结果。没有进行新事件端到端调查、重新登录抓取七平台或新的公开补查验收。新流程已接入默认编排，但本次在线验证使用的是已审冻结材料，仓内集成测试不能代替新任务线上验收。
